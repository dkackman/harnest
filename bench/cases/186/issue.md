## #186: Model catalog does not expose whether a repo is gated before a run is queued
filed by: @dkackman

**tool/endpoint:** `list_models` / `list_workflows(include_models=true)` / `validate_workflow` — model load pre-flight **repro:** queue a workflow whose model repo (e.g. a gated Hugging Face repo) requires license acceptance. The gate is not reported by any pre-flight surface; the 403 (HTTP 403 from the hub, `GatedRepoError`-class failure) surfaces only when the job runs and attempts the load. **expected:** the model listing/catalog (or `validate_workflow`) reports the gated/requires-licence status of a repo ahead of queueing, so a caller can predict the failure (or accept the licence) before spending queue time. **actual:** the gate is invisible until the job actually loads the model. First encountered with a 403 that only surfaced at run time; licence acceptance fixed it, but nothing pre-flight could have predicted it. **impact:** a gated repo is a predictable `validate_workflow`-visible condition, not something that should burn a queue and a worker load to discover.
